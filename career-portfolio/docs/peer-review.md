# Peer review

This page explains how to review the career research and how to record a useful change.

## Review task

1. Open one source from the [source log](/sources/).
2. Pick one detail, such as a job task, skill, or deadline.
3. Find where the site uses that detail.
4. Try the check listed on the [research page](/research/).
5. Write what you found, why it matters, and a useful next step.

The course directions for the current review round ask each student to file **3–5 constructive GitHub issues per classmate, per project**. Each issue should point to a specific observation, gap, or question and include a relevant page, source, or example.

## Record the decision

For each issue, the project owner decides to:

- **Accept** and make a change.
- **Investigate** and collect more evidence.
- **Defer** with a next step.
- **Decline** and explain why.

Keep the record connected:

**Issue → decision → linked documentation or code change → verification → reviewer retry.**

When accepting feedback, reference the issue number in the commit or pull request. Link the change in the issue and say exactly how it was checked. Ask the reviewer to retry before closing a resolved issue. Keep unfinished work open with its next step.

## Privacy

The full career reflection and personal eligibility circumstances stay in the private course submission. Do not put them in this public site or a public GitHub issue.
